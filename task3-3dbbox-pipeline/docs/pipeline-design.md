# 3D BBox 추출 파이프라인 — 현행 설계

> 이 문서가 **현재 유효한 설계**다. 라운드별 변경 이력은 [improvement-log.md](improvement-log.md)에 있다.
> 대상: Unitree G1 데이터셋 2종 (Brainco 8태스크, Humanoid Everyday 246태스크)

## 1. 목표

다운로드된 **전 데이터셋에 3D Bounding Box를 생성**하는 것이 최종 목표이고,
지금 단계는 그 생성기를 만드는 것이다. 따라서 세 가지를 만족해야 한다.

| 요구 | 대응 |
|---|---|
| **Robustness** — 실수 없이 검출 | 게이트를 스케일 불변량으로 구성, 실패 시 그리지 않음 |
| **설정 가능** — 완료 시간·산출물 조정 | `config.py`의 `RunConfig` / `PRESETS` |
| **미검증 에피소드에서도 동작** | 태스크 종류를 전부 덮어 검증, 파라미터를 데이터에서 유도 |

## 2. 파이프라인 5단계 (RoboBrain Pseudo-3D Annotation)

| 단계 | 모듈 | 우리 구현 |
|---|---|---|
| 1 | **GroundingDINO** | 텍스트 프롬프트 → 2D 박스. 저임계(0.20) 단일 패스 후 트래커가 강/약 판정 |
| 2 | **SAM 2.1** | 박스 → 인스턴스 마스크. 검출 실패 시 마지막 실검출에 앵커링한 창으로 전파 |
| 3 | **UniDepthV2 / 실측 depth** | Brainco는 추정(intrinsics도 함께 산출), HE는 parquet 실측 depth(mm) |
| 4 | **Back-projection** | 마스크 + depth + intrinsics → 객체별 점군 |
| 5 | **3D Box** | 점군 → axis-aligned 박스. 방식 A/B로 분기 |

## 3. 3D Box 2가지 방식

1~4단계는 공통이므로 **한 번 처리로 두 결과를 동시에** 낸다.

| | **방식 A — 관측된 것만** | **방식 B — 가림 보정** |
|---|---|---|
| 정의 | 실제로 보이는 픽셀만으로 박스 산출 | 가려진 부분을 고려한 물체 실제 크기 |
| 크기 기준 | 관측값 (EMA 스무딩) | 이력의 **상위 75분위** + 거울 보정 |
| 관측 끊김 시 | 그리지 않음 | `coast` — 실제 크기 유지하며 위치 추정 (최대 2.5초) |
| 기록 필드 | `center`, `size` | `center_amodal`, `size_amodal`, `coasting`, `conf` |

**거울 보정**: 단일 시점은 물체 뒷면을 볼 수 없어 깊이 방향 두께가 구조적으로 결손된다.
점군 앞면 기준으로 대칭 확장하되 관측 두께의 1.35배를 넘지 않는다.

## 4. 검증 게이트 — 스케일 불변량으로 구성

**설계 원칙**: 판정 기준이 카메라 거리나 물체 자세에 의존하면 다른 에피소드에서 반드시 깨진다.

| 게이트 | 기준 | 왜 일반화되나 |
|---|---|---|
| 물리 크기 | 2D 박스가 그 깊이에서 가리키는 폭 ≤ 0.75m | 거리에 **불변**. 픽셀 면적비는 거리²에 반비례해 head/wrist에서 100배 차이 났다 |
| 재투영 정합 | 3D 중심을 재투영한 점이 2D 박스 안 | 핀홀 모델상 반드시 성립하는 **불변량** |
| 회전불변 대각 | 대각이 이력 중앙값의 2배 이내 | AABB 변 길이는 회전만으로 √3배 변한다. 대각은 불변 |
| 절대 상한 | 최대 변 ≤ 0.80m | 전역 안전판 |
| 전파 크기 | 이력 대각의 0.55~1.8배 | 유령(빈 공간의 작은 박스)의 주 형태를 차단 |

**핵심 분리**: "그린다"와 "이력에 넣는다"를 나눈다. 게이트가 자기 이력과 비교하므로,
이력을 무비판 갱신하면 오염이 자기를 강화한다(실측: 이력 부피가 1020→9cm³로 붕괴한 사례).

## 5. 유령 방지 (물체가 시야를 벗어났을 때)

라운드2에서 승인 프레임의 7.5%가 유령이었다. 원인은 마스크 전파가
**자기 출력으로 자기 탐색창을 갱신**하는 닫힌 고리였다(창 면적 161,839 → 2,112px², 85프레임).

| 조치 | 내용 |
|---|---|
| 앵커링 | 전파 탐색창을 **마지막 실검출**에 고정. 되먹임 고리 자체를 끊는다(임계값 불필요) |
| 시간 제한 | 실검출 없이 1초 넘기면 전파 중단 |
| 크기 검증 | 이력 대각 대비 0.55~1.8배 밖이면 기각 |
| 계측 | `coverage_det` — 전파 승인을 뺀 실관측 비율. 기존 지표는 83% 유령을 0.98로 보고했다 |

## 6. 검출 프롬프트

- **Brainco 8태스크**: `meta/tasks.parquet` 지시문 기반. 단 **PickDrink는 지시문
  ("red cup")과 실물(파란 뚜껑 물병)이 다르므로** 상위 개념 어휘를 함께 넣는다.
- **HE**: 태스크명이 아니라 **description에 target object가 명시**되어 있다.
  246개 태스크의 description을 근거로 프롬프트를 만든다.

> 지시문을 그대로 믿으면 안 된다는 것이 PickDrink 사례의 교훈이다.
> 전체 적용 전에 **각 데이터셋의 실제 target object 목록 검토**가 선행돼야 한다.

## 7. 실행 설정 (`pipeline/config.py`)

```python
from config import PRESETS, RunConfig
cfg = PRESETS["balanced"]                         # 미리 정의된 조합
cfg = RunConfig(fps=3.0, cameras=["cam_left_high"], amodal=False)   # 직접 지정
```

| 프리셋 | fps | 카메라 | 에피소드 | 예상(GPU 2장) |
|---|---|---|---|---|
| `review` | 10 | 4대 | 전수 | 161h |
| `balanced` | 6 | 머리 2대 | 전수 | 78h |
| `fast` | 3 | 머리 1대 | 전수 | **25h** |
| `full` | 6 | 4대 | 전수 | 137h |
| `robust3` | 6 | 머리 2대 | **태스크당 3개** | **4.5h** |
| `robust5` | 6 | 머리 2대 | 태스크당 5개 | 7.4h |
| `visible_only` | 6 | 머리 2대 | 전수 | 78h (방식 B 없음) |

조정 가능한 주요 항목: `fps`(완료 시간에 정비례), `cameras`(대수에 정비례),
`episodes_per_task`(0=전수), `amodal`(가림 보정 여부), `save_video`(대량 시 끔).

## 8. 품질 지표의 위치 — 보조 수단

산출물 품질을 자동 판정하는 지표(`coverage_det`, `max_gap_s`, `peer_ratio`, `det_margin`)를
계산하지만, **이것으로 파라미터를 자동 조정하지 않는다.**

> 실측 사례: "화면의 12% 이상을 차지하면 오검출"이라는 지표가 손목 카메라에서
> **정상 물체를 잘라냈다.** 손목은 근접 촬영이라 물체가 화면을 채우는 것이 정상이다.

지표는 **대규모 실행에서 사람이 볼 표본을 고르는 용도**로만 쓰고,
품질 판정의 최종 근거는 육안 검증이다.

## 9. GPU 사용 (연구실 정책 준수)

- **PBS batch job으로만** 실행한다. interactive job과 job 없는 직접 실행은 금지다.
- Node 1은 job당 CPU 4개, Node 3은 8개 제한.
- job 이름 규칙: `G{GPU수}C{CPU수}_{이니셜}_{프로젝트}`

```bash
qsub -q pleiades1 -l select=1:ncpus=4:ngpus=1 -l walltime=05:00:00 pipeline/pbs_r4.sh
```

job 내부에서 재시도 루프를 돌리고, 완료된 유닛은 결과 파일 존재로 건너뛴다.
중단되어도 이어서 진행된다.

## 10. 파일 구성

```
pipeline/
├── config.py        실행 설정 (fps·카메라·산출물·샘플링)
├── spec.py          태스크별 프롬프트와 target object
├── geometry.py      역투영·점군정제·AABB·재투영검사·거울보정  (4~5단계, GPU 불필요)
├── models_wrap.py   GroundingDINO / SAM 2.1 / UniDepthV2 래퍼  (1~3단계)
├── track3d.py       추적·게이트·방식 A/B                        ← 핵심
├── run_review.py    15개 대표 검증 러너 (개선→평가 루프용)
├── queue_runner.py  대량 실행용 작업 큐 러너
└── pbs_*.sh         PBS job 스크립트
```
