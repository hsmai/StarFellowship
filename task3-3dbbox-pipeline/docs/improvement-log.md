# 개선 이력 — 육안 검증 기반 반복

> 현행 설계는 [pipeline-design.md](pipeline-design.md)에 있다. 이 문서는 **왜 그렇게 됐는지**의 기록이다.
> 각 라운드는 "구현 → 15개 대표 실행 → 육안 검증 → 원인 진단 → 수정"의 순환이다.
>
> **표기**: `V2`(개선 버전) = 라운드 2 = 결과 폴더 `review/r2` = 프로파일 `R2`.
> 최종 산출은 `review/r6`이고, robustness 실행 결과는 `robust/rb1`이다.

## 요약

| 라운드 | 핵심 변경 | 결과 |
|---|---|---|
| STEP 0~5 | 5단계 파이프라인 최초 구현 | Brainco 442프레임 동작, HE depth 검증(MAE 0.429m) |
| A~D | 추적·GT대조·4카메라·8태스크 확장 | 오레오 검출 52%→100%, 다만 12%가 박스 폭발 |
| V2 | 3중 게이트 + 마스크 덩어리 분리 | 폭발 12%→0%, red cup 13×17×30→6×9×3cm |
| V3 | target object 개념, 2방식 동시산출, HE 대표 재선정 | charger 오검출 해결(50,482px→6×6×2cm) |
| V4 | 스케일 불변 게이트, np.roll 버그 수정 | HE 7/7 개선 (bottle 13%→79%, towel 21%→100%) |
| V5 | 전파 앵커링, 가림 판정 재정초, 부속물 복원 | PickDrink 0%→100%, 꽃 줄기 포함 |
| **V6** | **V5의 과한 완화를 되돌림 + 태스크별 프로파일** | **완료 — 15태스크 39유닛 검증** |

## 라운드별 상세

### V2 — 박스 폭발 차단

**증상**: 물체를 옮기는 동안 3D box가 78×53×51cm로 폭발.

**원인**: "직전 프레임 박스를 위치 고정으로 재사용"하는 로직. 물체는 이동했는데 박스가
고정되어 배경을 마스크로 잡았다. 폭발 51건 중 **50건이 이 경로**였다.

**수정**: 3중 게이트(크기 급증·중심 점프·마스크 이상)로 기각. "틀린 박스를 그리느니 비운다."

### V3 — target object와 2가지 방식

- 태스크마다 **주 조작 대상**을 명시 지정. 이 라벨에만 엄격한 상한을 건다.
- 방식 A(관측만)와 B(가림 보정)를 **한 번 처리로 동시 산출**(1~4단계 공통).
- HE 대표를 **g1 + description에 target이 명시된 태스크**로 재선정.

### V4 — 스케일 불변량으로 전환

**증상 5가지가 같은 뿌리 3개에서 나왔다** (frames.json 7,901프레임 전수 분석):

1. 판정 기준이 스케일 가변량 — 면적비 0.12는 거리²에 반비례해 head/wrist에서 100배 차
2. 이력이 자기를 오염 — 가려진 박스가 기준을 끌어내려 정상 박스를 기각(부피 1020→9cm³)
3. 판정이 이진값이라 복구 경로 부재 — 38% 프레임이 박스 없음, 가림 보정 0회 호출

**순수 버그 발견**: `align_mask_to_depth`가 `np.roll`이라 **잘린 부분이 반대편으로 감겨 들어왔다**.
화면 끝 물체가 반대편 depth를 읽어(재투영 오차 606px) HE bottle 실패의 1차 원인이었다.

### V5 — 유령 되먹임 고리 절단

**증상**: 물체가 시야를 벗어나도 작은 박스가 남는다(사용자 최우선 지적).

**원인**: 마스크 전파가 **자기 출력으로 자기 탐색창을 갱신**하는 닫힌 고리.
마스크가 창을 다 못 채우면 창이 프레임당 0.97배로 줄어 복리로 붕괴한다.

| 실측 | |
|---|---|
| 탐색창 | 161,839px² → 2,112px² (85프레임) |
| 유령 프레임 | 승인 9,579 중 **721건(7.5%)** |
| 유령 트랙 13개 중 | **12개가 손목 카메라** |

**부수 발견**: 승인 7,232프레임 중 이력 반영이 **972건(13.4%)뿐**이고
**6,143건(84.9%)이 가림 오판으로 차단**됐다. 이것이 방식 B가 실제보다 작았던 이유다.

### V6 — 과한 완화를 되돌림 (현행)

**증상**: V5에서 얇은 부속물(토끼 귀·꽃 줄기)을 살리려 점군 필터를 완화했더니
**잘 되던 것이 무너졌다**.

| | V4 | V5 | 원인 |
|---|---|---|---|
| GraspOreo/머리좌 | 100% | **67%** | 배경·팔 혼입 |
| PickCharger/머리우 | 6×6×2cm | **8×28×30cm** | 깊이 방향 부풀음 |

사용자 평: *"작은 부분을 잡으려다 오히려 잘하던 걸 못하게 되는 경우가 다수.
어떻게 보면 진짜 r2가 더 나은 수준"*

**교훈**: 부속물 복원은 `same_depth_components`가 담당하므로 **점군 필터까지 완화할
이유가 없었다.** 한 문제를 고치려 여러 곳을 동시에 건드리면 회귀가 난다.

**되돌림**: 점군 필터 (10,90)+MAD 1.5, 부속물 깊이 허용 2cm 고정, 면적 제한 30%,
거울 보정 상한 1.35배.

**유지**: PickDrink 프롬프트(0→100%), 전파 앵커링, `coverage_det` 계측, HE 개선.

## 확인된 데이터 특성

| 발견 | 내용 |
|---|---|
| **PickDrink 라벨 오류** | 지시문은 "red cup"이지만 실물은 **파란 뚜껑 물병**(영상 확인). 지시문을 그대로 믿으면 안 된다 |
| HE 로봇 혼재 | g1 4,064 + h1 4,885 에피소드. 본 과제는 G1이므로 g1만 사용 |
| HE target 위치 | 태스크명이 아니라 **description에 명시**되어 있다 |
| RGB-depth 정렬 | HE는 depth가 RGB 대비 약 20px 어긋나 있다(STEP 0.5 실측) |
| HE intrinsics | 메타에 없어 FOV 70° 가정. 3D 크기가 상수배로 어긋날 수 있다 |
| depth 정확도 | UniDepthV2는 근접(0.3~0.8m)에서 오차 43%, 중거리(1~3m)에서 21.7% |

## 방법론에 대한 교훈

1. **한 번에 한 가지만 바꾼다.** V5에서 여러 곳을 동시에 완화해 회귀 원인 분리가 어려웠다.
2. **자동 품질 지표를 맹신하지 않는다.** "화면 12% 이상이면 오검출" 지표가
   손목 카메라에서 정상 물체를 잘랐다. 지표는 표본 선정용이고 판정은 육안이다.
3. **파라미터는 물리적 근거나 데이터에서 유도한다.** 15개 샘플에서 눈으로 맞춘 상수는
   다른 에피소드에서 깨진다.
4. **계측이 없으면 개선을 검증할 수 없다.** `coverage_det`가 없을 때는 83%가 유령인
   결과를 0.98로 보고했다.
