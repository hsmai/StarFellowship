# V6 — 보수적 원복 (2026-08-03 야간, 라운드4)

## 라운드3의 교훈

라운드3에서 얇은 부속물(토끼 귀·꽃 줄기)을 살리려고 점군 필터를 완화했더니
(백분위 10~90 → 2~98, MAD 1.5 → 3.0), **잘 되던 것이 무너졌다**.

| | 라운드2 | 라운드3 | 원인 |
|---|---|---|---|
| GraspOreo/머리좌 | 100% | **67%** (실관측 54%) | 배경·팔 혼입 |
| PickCharger/머리우 | 6×6×2cm | **8×28×30cm** | 깊이 방향 부풀음 |
| 루빅스/손목우 | 7cm급 | 28×24×16cm | 〃 |

사용자 평: *"작은 부분을 잡으려다 오히려 잘하던 걸 못하게 되는 경우가 다수.
어떻게 보면 진짜 r2가 더 나은 수준"*

## V6의 원칙 — 최소 변경

**r2를 기준선으로 삼고, r3에서 확실히 개선된 것만 남긴다.**

### 되돌린 것 (r2 값으로)

| 항목 | r3 | **V6** | 근거 |
|---|---|---|---|
| 점군 필터 | 백분위 (2,98), MAD 3.0 | **(10,90), MAD 1.5** | 완화가 배경·팔을 끌어들인 직접 원인 |
| 부속물 깊이 허용 | 물체 두께 비례 (1.5~5cm) | **고정 2cm** | 두꺼운 물체에서 허용치가 커져 손까지 합쳐짐 |
| 부속물 면적 제한 | 본체의 50% 이하 | **30% 이하** | 부속물은 본체보다 훨씬 작다 |
| 거울 보정 상한 | 관측 두께의 1.8배 | **1.35배** | 노트북 26cm, 먼지떨이 38cm 등 과대 |

부속물 복원은 `same_depth_components`가 담당하므로 점군 필터까지 완화할 이유가 없었다.

### 유지한 것 (r3의 확실한 개선)

- **PickDrink 프롬프트 수정** — 지시문은 "red cup"이지만 실물은 파란 뚜껑 물병.
  0% → 100%(6×11×7cm)로 해결됐고 회귀 위험이 없다.
- **전파 탐색창 앵커링** — 유령 되먹임 고리를 끊는 구조적 수정.
- **`coverage_det` 계측** — 전파 승인을 제외한 실관측 비율. 라운드2 지표는
  83%가 유령인 유닛을 0.98로 보고했다.
- **HE 7카테고리 개선** — 꽃 줄기 포함, 유령 제거.

### 새로 강화한 것 (유령 대응)

사용자 지적: *"target object가 카메라에 안 잡힐 때 다른 물체에 3d box를 씌운다",
"물건을 집지 않는 쪽 wrist에서 공백에 3d box를 잡는다"*

| 조치 | 내용 |
|---|---|
| 전파 시간 제한 | 실검출 없이 **1초**를 넘기면 전파하지 않는다 |
| 전파 크기 검증 | 이력 대각의 0.55~1.8배 밖이면 무조건 기각 (`ghost_size`) |
| 추적 연속성 | 직전 위치와 겹치는 후보 가중을 0.3 → 0.45 (이동 중 끊김 완화) |

방식 A는 **관측된 것만** 그리고, 그 구간은 방식 B의 `coast`가 명시적 추정으로 덮는다.
정보를 잃지 않으면서 "사라져야 할 때 사라진다"를 만족한다.

## 자동 품질 지표에 대한 입장 정정

라운드3에서 "정답 없이 에피소드 품질을 자동 판정하는 지표"를 설계했으나,
사용자 지적대로 **지표 자체가 틀릴 수 있다**.

> *"아까도 화면에서 n% 이상 차지하면 box 없는 걸로 출력했는데, wrist 쪽 카메라에서는
> 실제로 객체가 화면 꽉차게 등장하는 게 맞았으니까 그 객체에 대해서도 3d box를
> 검출해내야 했음. 변수가 너무 많으니 자체 판정 지표를 통해 self 개선을 할 생각이라면
> 아주 크게 잘못될 수도 있다."*

**정정된 방침**:
- 자동 지표는 **대규모 실행 시 사람이 볼 표본을 고르는 용도**로만 쓴다.
- 지표를 근거로 파라미터를 자동 조정(self-tuning)하지 않는다.
- 품질 판정의 최종 근거는 **육안 검증**이다.
- 지표가 놓치는 실패 유형(예: 크기가 계통적으로 작음)이 실제로 존재함을 명시한다.

## target object 정확도

사용자 지적: 검출을 일반화하면 엉뚱한 객체를 잡을 위험이 있다.

확인된 사실:
- **Brainco 8태스크**: 지시문과 실물이 일치. 단 **PickDrink만 불일치**
  (지시문 "red cup" vs 실물 파란 뚜껑 물병 — 영상으로 확인).
- **HE**: 태스크명이 아니라 **description에 target object가 명시**되어 있어,
  이를 근거로 7개 카테고리 대표를 선정했다.

→ 전체 데이터 적용 전에 **HE 246개 태스크의 description을 훑어 target object 목록을
작성**하는 것이 선행 과제다(내일 작업).
