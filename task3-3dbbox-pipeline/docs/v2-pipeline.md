# V2 파이프라인 — 튀는 박스 해결 + 전 태스크 커버 (2026-08-03)

## 문제 진단 (V1 결과 실측)

로봇이 물체를 옮기는 구간에서 3D box가 튀거나 사라졌다. 원인을 수치로 특정했다.

| | 개수 | 최대변 중앙값 |
|---|---|---|
| 정상 검출 프레임 | 232 | 11.0 cm ✅ |
| 박스 전파 프레임 | 210 | 15.7 cm |
| **30cm 초과 폭발** | **51 (12%)** | **그중 50건이 박스 전파** |

직접 원인은 V1의 "직전 프레임 박스를 위치 고정으로 재사용"하는 로직이다. 물체는 이미 이동했으므로
어긋난 박스가 SAM에 들어가 배경(바닥·의자)을 마스크로 잡고, 배경 depth가 섞여 박스가 폭발했다.

## V2 설계 (`pipeline/track3d.py`)

파이프라인 5단계 구성은 그대로 두고, 2단계(추적)와 5단계(박스 산출) 사이에 검증층을 넣었다.

**놓친 물체 3단 폴백** — 이동 중에도 따라가도록:
1. 정상 검출 (임계 0.35)
2. **저임계 재검출** (0.20) — 직전 위치와 겹치는 후보만 인정
3. **SAM 마스크 전파** — 마스크 결과로 박스를 매 프레임 갱신 (V1과 결정적 차이)

**3중 게이트** — 정상 검출분 포함 전부에 적용, 하나라도 걸리면 그 프레임은 박스를 그리지 않는다:

| 게이트 | 기준 | 잡는 증상 |
|---|---|---|
| 크기 | 변이 이력 중앙값 2.5배↑ 또는 부피 4배↑ | 박스 폭발 |
| 이동 | 3D 중심 0.25m 초과 점프 | 엉뚱한 곳으로 튐 |
| 마스크 | 채움비 10~98% 이탈 / depth 급변 | 배경 잡은 마스크 |

**추가**: EMA 스무딩(떨림 제거), 마스크를 검출박스 1.15배 내로 제한(케이블 유입 차단),
doll·tissue·charger 프롬프트 교체.

## 실행 범위 — 태스크별 균등 샘플링

에피소드는 같은 태스크의 반복 시도라 전수 처리는 중복이 크다. **모든 태스크 종류를 커버**하는 것이
파이프라인 검증의 핵심이므로 태스크별로 균등 샘플링했다 (seed 고정, 재현 가능).

| 데이터셋 | 태스크 | 에피소드 | 프레임 (3fps) |
|---|---|---|---|
| Brainco | 8 / 8 (전부) | 160 (태스크당 20) | 12,800 |
| Humanoid Everyday | 246 / 246 (전부) | 1,174 (태스크당 5) | 46,960 |
| **합계** | **254** | **1,334** | **59,760** |

- HE 246개 태스크의 검출 프롬프트는 태스크명에서 자동 생성 (`pipeline/prompts_he.py`)
- 대표 15건(Brainco 8태스크 + HE 7카테고리)은 큐 맨 앞에 배치해 육안 검증을 먼저 할 수 있게 했다

## 작업 큐 구조 (`pipeline/queue_runner.py`)

GPU가 끊겨도 진행분이 남고 재실행하면 이어서 진행된다.

- **claim**: `mkdir` 원자성으로 락 → 두 워커가 같은 에피소드를 잡지 않는다
- **done**: 결과 JSON 기록 시 완료. 재시작 시 건너뛴다
- **stale**: 워커가 죽어 claim만 남으면 1시간 후 회수해 다른 워커가 처리
- 워치독이 워커를 자동 재시작 (`pipeline/watchdog_queue.sh`)

```bash
python queue_runner.py build          # 큐 생성
python queue_runner.py work <id>      # 워커 (GPU당 1개)
python queue_runner.py status         # 진행률
```

## 산출물

- `v2/out/<job>.json.gz` — 전 에피소드 프레임별 3D box (압축)
- `v2/rep/` — 대표 15건 오버레이 영상 + 정지 이미지(중간 프레임 / 이동 구간)
- `v2/done/<job>.json` — 에피소드별 통계 (커버리지, 기각 사유, 크기 중앙값)


## 실행 결과 — Brainco 대표 8태스크 (2026-08-03 12:45)

8개 태스크 전부에서 파이프라인이 동작했다. V1의 80cm급 폭발은 완전히 사라졌으나,
물체 3종에서 박스가 실제보다 크게 잡히는 문제가 남았다.

| 태스크 | 조작 물체 | 승인률 | 크기 중앙값 | 판정 |
|---|---|---|---|---|
| GraspOreo | oreo | 79% | 10×5×3 cm | ✅ 실물 부합 |
| GraspRubiksCube | rubiks cube | 100% | 7×7×3 cm | ✅ |
| PickApple | apple | 100% | 7×6×3 cm | ✅ |
| PickTissues | tissue pack | 96% | 10×9×4 cm | ✅ |
| PickToothpaste | toothpaste | 79% | 7×2×2 cm | ✅ |
| PickCharger | charger | 91% | **8×22×21 cm** | ⚠️ 케이블 포함 |
| PickDoll | doll | 100% | **29×28×14 cm** | ⚠️ 다소 부풂 |
| PickDrink | red cup | 75% | **13×17×30 cm** | ⚠️ 팔·그림자 혼입 |

접시(plate)는 8태스크 전부 91~100% 승인, 17~30cm로 안정적이다.

**남은 문제의 원인**: 마스크가 여러 덩어리로 나뉠 때(충전기 본체+케이블, 컵+로봇팔 그림자)
전부 하나의 점군으로 합쳐진다. 마스크를 검출박스 1.15배로 제한했으나 박스 자체가 클 때는
효과가 없다.

**개선안**: 마스크의 **최대 연결 성분만 사용**(cv2.connectedComponents) + 점군의 z축 산포가
과도할 때 주 클러스터만 남기기.


## V2.1 개선 — 마스크 덩어리 분리 (2026-08-03 13:00)

1차 결과에서 charger·red cup·doll의 박스가 실제보다 컸다. 원인은 마스크가 여러 덩어리로
나뉠 때(충전기 본체+케이블, 컵+로봇팔 그림자) 전부 한 점군으로 합쳐지는 것이었다.

**추가한 3가지** (`geometry.py`, `track3d.py`)

| 항목 | 내용 |
|---|---|
| `largest_component()` | 마스크에서 가장 큰 연결 덩어리만 사용 — 케이블·그림자 분리 |
| `cluster_depth()` | 점군을 깊이로 정렬해 6cm 이상 간격에서 끊고 주 덩어리만 취함 (MAD는 대칭이라 한쪽 치우친 혼입을 놓침) |
| 절대 크기 상한 게이트 | 라벨별 상한(기본 35cm, plate·doll 45cm, person 2.2m 등) 초과 시 이력 없이 즉시 기각 |
| 전경 분리 강화 | `foreground_mad` 2.0 → 1.5 |

**효과 (동일 에피소드 비교)**

| 물체 | V2 | **V2.1** | 판정 |
|---|---|---|---|
| red cup | 13×17×30 cm | **6×9×3 cm** | ✅ 해결 |

| oreo | 10×5×3 cm | 9×5×2 cm | ✅ 유지 |

## 샘플링 재조정 — 6fps

영상이 부드럽게 보이도록 3fps → **6fps**(stride 10 → 5)로 올리고, 총 처리량을 8시간 안에
맞추기 위해 에피소드 수를 줄였다.

| | 이전 | **현재** |
|---|---|---|
| 샘플링 | 3fps | **6fps** |
| Brainco | 태스크당 20개 (160ep) | 태스크당 12개 (96ep) |
| HE | 태스크당 5개 (1,174ep) | 태스크당 3개 (738ep) |
| 태스크 커버 | 254/254 | **254/254 (동일)** |
| 예상 소요 | 4.3시간 | 약 5.3시간 |

## 실행 절차 — 대표 우선 검증

`queue_runner.py work <id> --rep` 로 **대표 15건만 처리하고 멈추는 모드**를 추가했다.
육안 검증을 통과한 뒤 전체를 돌리는 2단계 구조다.

```bash
tmux new -d -s t3r0 'bash pipeline/watchdog_queue.sh r0 0 rep'   # 대표만
tmux new -d -s t3w0 'bash pipeline/watchdog_queue.sh w0 0'       # 전체
```
