# V2 파이프라인 — 튀는 박스 해결 + 전 태스크 커버 (2026-08-03)

## 문제 진단 (V1 결과 실측)

로봇이 물체를 옮기는 구간에서 3D box가 튀거나 사라졌다. 원인을 수치로 특정했다.

| | 개수 | 최대변 중앙값 |
|---|---|---|
| 정상 검출 프레임 | 232 | 11.0 cm ✅ |
| 박스 전파 프레임 | 210 | 15.7 cm |
| **30cm 초과 폭발** | **51 (12%)** | **그중 50건이 박스 전파** |

직접 원인은 V1의 "직전 프레임 박스를 위치 고정으로 재사용"하는 로직이다. 물체는 이미 이동했으므로
어긋난 박스가 SAM에 들어가 배경(바닥·의자)을 마스크로 잡고, 배경 depth가 섞여 박스가 폭발했다.

## V2 설계 (`pipeline/track3d.py`)

파이프라인 5단계 구성은 그대로 두고, 2단계(추적)와 5단계(박스 산출) 사이에 검증층을 넣었다.

**놓친 물체 3단 폴백** — 이동 중에도 따라가도록:
1. 정상 검출 (임계 0.35)
2. **저임계 재검출** (0.20) — 직전 위치와 겹치는 후보만 인정
3. **SAM 마스크 전파** — 마스크 결과로 박스를 매 프레임 갱신 (V1과 결정적 차이)

**3중 게이트** — 정상 검출분 포함 전부에 적용, 하나라도 걸리면 그 프레임은 박스를 그리지 않는다:

| 게이트 | 기준 | 잡는 증상 |
|---|---|---|
| 크기 | 변이 이력 중앙값 2.5배↑ 또는 부피 4배↑ | 박스 폭발 |
| 이동 | 3D 중심 0.25m 초과 점프 | 엉뚱한 곳으로 튐 |
| 마스크 | 채움비 10~98% 이탈 / depth 급변 | 배경 잡은 마스크 |

**추가**: EMA 스무딩(떨림 제거), 마스크를 검출박스 1.15배 내로 제한(케이블 유입 차단),
doll·tissue·charger 프롬프트 교체.

## 실행 범위 — 태스크별 균등 샘플링

에피소드는 같은 태스크의 반복 시도라 전수 처리는 중복이 크다. **모든 태스크 종류를 커버**하는 것이
파이프라인 검증의 핵심이므로 태스크별로 균등 샘플링했다 (seed 고정, 재현 가능).

| 데이터셋 | 태스크 | 에피소드 | 프레임 (3fps) |
|---|---|---|---|
| Brainco | 8 / 8 (전부) | 160 (태스크당 20) | 12,800 |
| Humanoid Everyday | 246 / 246 (전부) | 1,174 (태스크당 5) | 46,960 |
| **합계** | **254** | **1,334** | **59,760** |

- HE 246개 태스크의 검출 프롬프트는 태스크명에서 자동 생성 (`pipeline/prompts_he.py`)
- 대표 15건(Brainco 8태스크 + HE 7카테고리)은 큐 맨 앞에 배치해 육안 검증을 먼저 할 수 있게 했다

## 작업 큐 구조 (`pipeline/queue_runner.py`)

GPU가 끊겨도 진행분이 남고 재실행하면 이어서 진행된다.

- **claim**: `mkdir` 원자성으로 락 → 두 워커가 같은 에피소드를 잡지 않는다
- **done**: 결과 JSON 기록 시 완료. 재시작 시 건너뛴다
- **stale**: 워커가 죽어 claim만 남으면 1시간 후 회수해 다른 워커가 처리
- 워치독이 워커를 자동 재시작 (`pipeline/watchdog_queue.sh`)

```bash
python queue_runner.py build          # 큐 생성
python queue_runner.py work <id>      # 워커 (GPU당 1개)
python queue_runner.py status         # 진행률
```

## 산출물

- `v2/out/<job>.json.gz` — 전 에피소드 프레임별 3D box (압축)
- `v2/rep/` — 대표 15건 오버레이 영상 + 정지 이미지(중간 프레임 / 이동 구간)
- `v2/done/<job>.json` — 에피소드별 통계 (커버리지, 기각 사유, 크기 중앙값)
