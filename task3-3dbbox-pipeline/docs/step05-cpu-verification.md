# STEP 0.5 — GPU 없이 가능한 준비·검증 (2026-08-02)

> 파이프라인 6단계 중 **4~5단계(Back-projection, 3D Box)는 GPU가 필요 없다.**
> Humanoid Everyday의 **실측 depth**를 입력으로 쓰면 GPU 승인 전에 이 부분을 완성·검증할 수 있어 먼저 수행했다.
> GPU가 필요한 부분은 1~3단계(GroundingDINO 검출 / SAM 2.1 마스크 / UniDepthV2·WildCamera 추정)뿐이다.

## 1. 산출물

| 파일 | 내용 |
|---|---|
| `pipeline/geometry.py` | 4~5단계 구현체 — 역투영, 점군 정제, axis-aligned 3D box, 3D→2D 재투영·시각화 |
| `results/task3_step05_final.png` | 최종 검증 결과 (실측 depth + 정확한 마스크 → 3D box) |
| `results/task3_align.png` | RGB-depth 정렬 진단 |
| `results/task3_step05_compare.png` | 마스크 정밀도에 따른 박스 품질 비교 |

SAM 2.1 마스크는 아직 없으므로, **색상 기반 마스크(HSV)로 대체**해 로직을 검증했다. GPU 확보 후 이 자리에 SAM 마스크만 꽂으면 그대로 동작한다.

## 2. 검증 결과

### 2-1. 역투영·intrinsics 타당성 — 통과

두 데이터셋 모두 카메라 intrinsics가 메타에 없어 **HFOV 70° 가정으로 근사**(WildCamera 추정치가 들어올 자리)했다. 타당성은 "책상 평면이 실제로 평면으로 복원되는가"로 검증:

- 책상 영역 19,135점 평면 적합 → **잔차 평균 5.3mm**
- 전체 장면 역투영 264,199점, z 범위 0.27~2.71m (실내 규모로 타당)

### 2-2. 발견 ① — RGB와 depth가 약 20px 어긋나 있음

엣지 상관 분석으로 진단:

| | 엣지 일치 픽셀 |
|---|---|
| 무보정 | 236 |
| **dx=+20 이동 시** | **343 (최대)** |

→ HE의 depth 맵이 RGB 대비 수평으로 약 20px 시프트되어 있다. RGB 기준 마스크를 그대로 depth에 적용하면 **경계에서 배경 거리값이 섞인다.** 원 파이프라인에 없는 `align_mask_to_depth()` 보정 단계를 추가했다.

### 2-3. 발견 ② — 마스크가 정확해도 박스가 부풀어 오름

**정제 설정별 3D 박스 크기 비교** (대상: 주황 그릇, 실제 지름 약 25cm):

| 설정 | 크기 (W×H×D) | 거리 |
|---|---|---|
| A. percentile(5,95)만 — 초기 구현 | 40.5 × 46.6 × **81.5** cm | 0.91m |
| B. + 모드 필터 (중앙값±3·MAD) | 32.7 × 29.0 × **21.7** cm | 0.61m |
| C. + 마스크 erosion 5px | 32.5 × 27.3 × 21.4 cm | 0.60m |
| D. + 정렬 보정 (dx=−20) | 34.3 × 23.4 × 21.1 cm | 0.60m |
| **E. + MAD 2.0 강화 (채택)** | **34.3 × 20.9 × 17.7 cm** | **0.60m** |

**percentile 클리핑만으로는 부족했다.** 마스크 내 depth 히스토그램이 0.5~0.65m(그릇 60%)와 1.3m 이상(배경 꼬리)으로 갈라져 있어, percentile은 꼬리를 못 자르고 z 깊이가 실제의 **약 5배(82cm)** 로 부풀었다. 중앙값±k·MAD 기반 **전경 분리**를 추가하자 17.7cm로 수렴했다.

최종 박스는 실제 그릇 크기와 부합한다(가로 34cm는 그릇 테두리+그림자 포함, 깊이 17.7cm는 그릇 두께로 타당).

## 3. 구현 확정 사항 (RoboBrain 리포트 미공개 세부에 대한 우리 방침)

STEP 0에서 정리한 미공개 항목을 **실측으로 검증해 확정**했다:

| 항목 | STEP 0 계획 | STEP 0.5 확정 |
|---|---|---|
| 점군 이상치 제거 | percentile 클리핑 + statistical outlier | **모드 기반 전경 분리(중앙값±2·MAD)를 최우선 적용** ← 실측으로 필요성 확인 |
| 마스크 경계 처리 | erosion 2~3px | erosion 5px (효과 있으나 모드 필터 대비 영향 작음) |
| 3D 박스 산출 | axis-aligned min/max | 동일 (리포트 명시 방식 유지) |
| 좌표계 | 카메라 좌표계 | 동일 |
| **정렬 보정** | (계획에 없던 항목) | **추가** — HE는 dx≈−20px |

## 4. GPU 확보 후 남은 작업

| 단계 | 상태 |
|---|---|
| 1. GroundingDINO 2D 검출 | 미구현 (GPU 필요) |
| 2. SAM 2.1 마스크 + 추적 | 미구현 (GPU 필요) — **현재 색상 마스크가 들어간 자리** |
| 3. UniDepthV2 depth + WildCamera intrinsics | 미구현 (GPU 필요) — **현재 실측 depth + FOV 가정이 들어간 자리** |
| 4. Back-projection | ✅ 완료·검증 |
| 5. 3D Box + 시각화 | ✅ 완료·검증 |

즉 **파이프라인의 후반부는 이미 동작하는 상태**이며, GPU 확보 시 앞단 3개 모델만 연결하면 된다.

## 5. Brainco 트랙에 대한 함의

Brainco에는 실측 depth가 없어 이번 검증을 직접 할 수 없다. 다만 이번에 확인된 두 가지가 그대로 적용된다:
- **모드 기반 전경 분리는 필수** (추정 depth는 경계에서 더 부정확할 가능성이 높음)
- intrinsics는 WildCamera 추정에 의존 → 오차가 박스 크기에 직결. HE에서 측정할 "추정 depth vs 실측 depth" 오차를 Brainco 신뢰도의 간접 근거로 삼는다 (STEP 4).
